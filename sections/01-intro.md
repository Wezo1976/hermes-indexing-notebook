# Introduction

This section summarizes the purpose and tone of the contributing guide for the project.

## Community mindset

> _A real community, however, exists only when its members interact in a meaningful way that deepens their understanding of each other and leads to learning._

The guide opens by framing contribution as a community activity, not just a code submission process. Contributors are expected to improve the project while also helping maintain constructive collaboration.

## When to contribute

The project invites contributions when you:

- want to support the project,
- have an idea that could improve how it works, or
- notice an error that should be fixed.

## Basic contribution flow

The expected workflow is intentionally simple:

1. Fork the repository.
2. Make your fixes or improvements in your fork.
3. Open a pull request against the `master` branch.

## What this means in practice

A good contribution should:

- focus on a clear improvement,
- be prepared in your own branch or fork before review, and
- be submitted through the pull request process so it can be discussed.
